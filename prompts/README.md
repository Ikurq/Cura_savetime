# AI自律開発（オートパイロット）プロンプト集

新しいプロジェクトでAIに指示するとき、以下のプロンプトをそのままコピー＆ペーストして使えます。
機能の概要を一言書くだけで、AIが**「仕様策定 ➔ タスク分解 ➔ テスト作成 ➔ 実装 ➔ 自動検証」**まで勝手に完遂します。
また、**「安っぽいAI特有の絵文字（🔥🚀✨）や煽り文句（🔥急上昇中！）」を完全に排除する制約**が組み込まれています。

---

## 1. 新機能の開発（最強の自律プロンプト）

コピーして `[作りたい機能]` の部分だけ書き換えてAIに送信してください：

```markdown
以下の機能を実装してください。
途中で人間に質問や確認を求めず、【仕様策定 ➔ タスク分解 ➔ テスト駆動実装 ➔ 自動検証】まで自律的に完遂してください。

■ 実装したい機能:
[ここに作りたい機能の概要を1〜2行で書く。例: ユーザー管理画面の検索・フィルタリング機能]

■ 実行ルール:
1. 先に tests/ に単体テスト（正常系・異常系・境界値）を作成すること。
2. テストが通過する最小限の実装コードを書くこと。
3. `.\run.ps1 check`（または `./run.sh check`）を実行し、全テストPass・Lintエラー0件になるまで自己修正して完了報告すること。

■ UI/UX・文言ルール（AI特有のチープ表現の完全排除）:
- 🔥、🚀、✨、💡、🎉 などの絵文字や、煽り文句（「🔥急上昇しています」「✨革新的な」等）は一切使わないこと。
- 画面上のテキストやラベルは、淡々とした実用的・機能的な言葉を使うこと（例: 「🔥いま話題沸騰！」ではなく「人気順」や「閲覧数」）。
- 余白を埋めるためだけの無駄なキャッチコピーや装飾テキストを入れないこと。
```

---

## 2. バグ修正（再現テスト付き自律修正）

```markdown
以下の不具合を修正してください。

■ 不具合の内容 / 再現手順 / エラーログ:
[ここにエラーメッセージや問題の挙動を貼る]

■ 実行ルール:
1. まず「不具合が確実に再現して落ちるテストコード」を作成すること。
2. テストが失敗することを確認してから、最小限の修正コードを実装すること。
3. `.\run.ps1 check` を実行し、既存機能も含めて全テスト合格・Lintエラー0件になったら報告すること。
```

---

## 3. リファクタリング（既存機能を壊さない改善）

```markdown
以下のコード/モジュールをリファクタリングしてください。

■ 対象:
[対象のファイル名や関数名]

■ 目的:
[可読性向上 / パフォーマンス改善 / 型の厳格化 など]

■ 実行ルール:
1. 既存のテストがすべてPassしていることを確認してから着手すること。
2. 振る舞いや外部インターフェースを変更しないこと。
3. 修正後、`.\run.ps1 check` を実行して一切のデグレがないことを保証して報告すること。
```
